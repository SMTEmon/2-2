## 🔗 Disjoint Set Union (DSU)
Before understanding Kruskal's Algorithm, we must understand the **Disjoint Set Union (DSU)** data structure. 
- **Purpose in MST:** In Kruskal's, we add edges one by one. We must ensure that adding a new edge **does not form a cycle**. DSU perfectly handles this by keeping track of which vertices belong to which connected component.
- If two vertices of an edge belong to the *same* set, adding the edge forms a cycle. If they belong to *different* sets, it is safe to add the edge and we *unite* the sets.

### DSU Implementation (C++)
The code provided in the lecture uses two vital optimizations: **Path Compression** (in `find`) and **Union by Rank** (in `unite`).

```cpp
// Disjoint set data structure
class DSU {
    vector<int> parent, rank;

public:
    // Initialization
    DSU(int n) {
        parent.resize(n);
        rank.resize(n);
        for (int i = 0; i < n; i++) {
            parent[i] = i; // Every node is its own parent initially
            rank[i] = 1;   // Initial rank/depth is 1
        }
    }

    // Find with Path Compression
    int find(int i) {
        // If i is the parent of itself, return i. 
        // Else recursively find the parent and compress the path.
        return (parent[i] == i) ? i : (parent[i] = find(parent[i]));
    }

    // Union by Rank
    void unite(int x, int y) {
        int s1 = find(x), s2 = find(y);
        
        if (s1 != s2) {
            // Attach smaller rank tree under root of higher rank tree
            if (rank[s1] < rank[s2]) 
                parent[s1] = s2;
            else if (rank[s1] > rank[s2]) 
                parent[s2] = s1;
            else {
                parent[s2] = s1;
                rank[s1]++;
            }
        }
    }
};
```

## 🥈 Kruskal’s Algorithm
Unlike Prim's which grows a single tree outward from a source, Kruskal's algorithm looks at **all edges** globally and greedily picks the absolute cheapest edges available, using DSU to fuse them into a single tree.

### Algorithm Steps:
1. **Sort** all the edges in a non-decreasing order of their weight.
2. Pick the **smallest edge**.
3. Check if it forms a cycle with the spanning tree formed so far, using **Disjoint Set Union (DSU)**.
4. If the cycle is not formed, include this edge. Else, discard it.
5. Repeat steps 2–4 until there are exactly **$(V-1)$** edges in the spanning tree.

### 💻 Pseudocode (C++)
```cpp
// Comparator to sort edges based on weight (the 3rd element: a[2])
bool comparator(vector<int> &a, vector<int> &b){
    return a[2] < b[2]; 
}

int kruskalsMST(int V, vector<vector<int>> &edges) {
    
    // 1. Sort all edges
    sort(edges.begin(), edges.end(), comparator);
    
    // 2. Initialize DSU
    DSU dsu(V);
    int cost = 0, count = 0;
    
    // 3. Traverse edges in sorted order
    for (auto &e : edges) {
        int x = e[0], y = e[1], w = e[2];
        
        // 4. Make sure there is no cycle (they belong to different sets)
        if (dsu.find(x) != dsu.find(y)) {
            dsu.unite(x, y); // Merge the sets
            cost += w;       // Add edge weight to total cost
            
            // 5. Stop early if we have V-1 edges
            if (++count == V - 1) break; 
        }
    }
    return cost;
}
```

## ⏱️ Complexity Analysis: Kruskal's Algorithm

> [!abstract] Final Complexity
> - **Time Complexity:** $\mathcal{O}(E \log V)$
> - **Space Complexity:** $\mathcal{O}(V+E)$

### 1. Time Complexity Derivation: Step-by-Step
Let $V$ be the number of vertices and $E$ be the number of edges.

1. **Sorting the edges:** Sorting an array of $E$ edges takes $\mathcal{O}(E \log E)$ time.
2. **DSU Initialization:** Creating the `parent` and `rank` arrays takes $\mathcal{O}(V)$ time.
3. **Iterating through edges (DSU Operations):** 
    - We loop through at most $E$ edges.
    - Inside the loop, we perform `find` and `unite` operations. With Path Compression and Union by Rank, these take nearly $\mathcal{O}(1)$ time (specifically, Inverse Ackermann function $\alpha(V)$). However, in older standard academic analyses (without strict amortized bounds), a single DSU operation might be bounded by $\mathcal{O}(\log V)$. 
    - Total time for DSU operations is bounded by $\mathcal{O}(E \log V)$.

**Combining it all algebraically:**
$$ \text{Total Time} = \mathcal{O}(E \log E) + \mathcal{O}(E \log V) $$

*Wait, how does this equal $\mathcal{O}(E \log V)$ as stated in the slides?*
- In any simple graph, the maximum number of edges is $E \le V^2$.
- If we take the logarithm of both sides: $\log E \le \log (V^2)$.
- Using logarithm rules: $\log E \le 2 \log V$.
- Therefore, asymptotically, **$\mathcal{O}(\log E)$ is the same as $\mathcal{O}(\log V)$**.

Substituting this back into our formula:
$$ \mathcal{O}(E \log E + E \log V) \equiv \mathcal{O}(E \log V + E \log V) = \mathcal{O}(E \log V) $$

### 2. Space Complexity Derivation: Step-by-Step
1. **Graph/Edge List Representation:** Storing all the edges requires $\mathcal{O}(E)$ space.
2. **DSU Data Structures:** The `parent` and `rank` arrays each require $\mathcal{O}(V)$ space.
3. **Sorting Overhead:** Depending on the sorting algorithm used under the hood (e.g., IntroSort in C++), it may take $\mathcal{O}(\log E)$ stack space, which is negligible compared to $V$ and $E$.

**Total Space Complexity:**
$$ \text{Total Space} = \mathcal{O}(E) + \mathcal{O}(V) = \mathcal{O}(V + E) $$
