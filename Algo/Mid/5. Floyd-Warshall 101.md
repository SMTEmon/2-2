# Graph 3: All Pair Shortest Path (Floyd-Warshall)

> [!abstract] What is the All Pair Shortest Path (APSP) Problem?
> Given a weighted directed or undirected graph, the goal is to find the shortest distance between **every possible pair of vertices** in the graph.

> [!question] Can we just use Dijkstra or Bellman-Ford?
> Yes, you *could* run a Single-Source Shortest Path (SSSP) algorithm like Dijkstra or Bellman-Ford from *every single vertex*. 
> - **Dijkstra from all nodes:** Time complexity would be $O(V \cdot E \log V)$. However, Dijkstra **fails with negative edge weights**.
> - **Bellman-Ford from all nodes:** Handles negative weights, but time complexity becomes $O(V \cdot V \cdot E) = O(V^4)$ for dense graphs, which is very slow. 

> [!success] The Solution: Floyd-Warshall Algorithm
> Floyd-Warshall is a dynamic programming algorithm that finds shortest paths for **all sources at once**. 
> - Works perfectly with **negative edge weights**.
> - **Cannot** find a path if there are **negative cycles**, but it *can* be used to detect them.

---

## 🧠 Core Concept & Recurrence Relation

The key insight of the Floyd-Warshall algorithm is to ask: 
*"Can we find a shorter path from vertex $i$ to vertex $j$ by taking a detour through an intermediate vertex $k$?"*

We build up the solution iteratively. We try setting every vertex $1, 2, ..., n$ as an intermediate vertex one by one and check if it improves the known distance between any pairs.

> [!info] The Recurrence Relation
> $$dist[i][j] = \min(dist[i][j], \quad dist[i][k] + dist[k][j])$$
> - $dist[i][j]$: Current shortest distance from $i$ to $j$.
> - $dist[i][k] + dist[k][j]$: Distance from $i$ to $j$ routing through intermediate node $k$.

---

## 💻 Algorithms and Code

### 1. Complete Pseudocode

```text
Algorithm: Floyd-Warshall
Data: A directed/undirected weighted graph G(V, E)
Result: Matrix dist[][] containing shortest paths between all pairs

// 1. Initialization Phase
n = cardinality(V)
Initialize a matrix dist[n][n] with Infinity (∞)

for each vertex v in V:
    dist[v][v] = 0           // Distance to itself is 0

for each edge (u, v) in E:
    dist[u][v] = weight(u, v) // Distance of direct edges

// 2. Main Algorithm Phase
for k = 0 to n-1:             // Intermediate vertex
    for i = 0 to n-1:         // Source vertex
        for j = 0 to n-1:     // Destination vertex
            if dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]
```

### 2. C++ Implementation Implementation

```cpp
// INF is a very large number representing Infinity
for (int k = 0; k < V; k++) {          // Pick intermediate vertex one by one
    for (int i = 0; i < V; i++) {      // Pick source vertex
        for (int j = 0; j < V; j++) {  // Pick destination vertex
            
            // Check if k acts as a shorter path from i to j
            // Also ensure we don't add to INF, causing integer overflow
            if (dist[i][k] != INF && dist[k][j] != INF) {
                dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j]);
            }
        }
    }
}
```

## ⏱️ Complexity Analysis

> [!tip] Time Complexity: $O(V^3)$
> **Step-by-step breakdown:**
> 1. The algorithm relies on three deeply nested loops:
>    - The outer loop `k` iterates over all vertices ($V$ times).
>    - The middle loop `i` iterates over all vertices ($V$ times).
>    - The inner loop `j` iterates over all vertices ($V$ times).
> 2. Inside the innermost loop, checking and updating the minimum distance is an $O(1)$ constant time operation.
> 3. Total operations = $V \times V \times V \times O(1) = O(V^3)$.

> [!tip] Space Complexity: $O(V^2)$
> **Step-by-step breakdown:**
> 4. To store the shortest distance between *every* pair of nodes, we must create a 2D array (matrix).
> 5. The rows represent the starting vertex ($V$ rows) and the columns represent the destination vertex ($V$ columns).
> 6. Therefore, the size of the matrix is $V \times V$, resulting in $O(V^2)$ auxiliary space.

## 🚫 Negative Edge Cycle Detection

A negative cycle is a loop in a graph where the total sum of edge weights is a negative number. If a graph has a negative cycle, you can keep looping through it forever to infinitely decrease your path cost. No shortest path exists in this case.

> [!warning] How it works
> - Before the algorithm runs, the distance from any node to itself `dist[i][i]` is strictly `0`.
> - If we route a path from $i \to ... \to i$ and the total weight is **negative**, the Floyd-Warshall algorithm will update `dist[i][i]` to be a negative number.
> - Therefore, if `dist[i][i] < 0` for any vertex $i$ after the algorithm finishes, a negative cycle exists!

```cpp
// Pseudocode for cycle detection (Run AFTER Floyd-Warshall completes)
for i = 0 to V - 1:
    if dist[i][i] < 0:
        return "Negative cycle detected"
```
