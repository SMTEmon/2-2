# Dijkstra's Shortest Path Algorithm: Correctness & Proof

> [!info] Problem Setup
> Let $G = (V, E, w)$ be a weighted directed graph.
> - **Weights:** $w : E \to \mathbb{R}_{\ge 0}$ (Assigns **non-negative** weights to edges).
> - **Source:** Fix a source vertex $s \in V$.
> - **Shortest-path distance:** Denoted as $\delta(s, v)$ from $s$ to $v$.
> $$ \delta(s, v) = \begin{cases} \min\{w(p) : p \text{ is a path from } s \text{ to } v\} & \text{if a path exists} \\ \infty & \text{otherwise} \end{cases} $$

## The Algorithm

> [!code] Algorithm: Dijkstra($G, s$)
> ```python
> 1. d[s] = 0; 
> 2. d[v] = ∞ for all v ≠ s
> 3. S = ∅                           # Set of finalized vertices
> 4. Q = V                           # Min-priority queue keyed by d[·]
> 5. 
> 6. while Q is not empty:
> 7.     u = Extract-Min(Q)          # Get unvisited node with smallest d[]
> 8.     S = S ∪ {u}                 # Mark u as finalized
> 9.     
> 10.    for each neighbor v of u:
> 11.        if d[u] + w(u, v) < d[v]:  # Relaxation Step
> 12.            d[v] = d[u] + w(u, v)
> ```

---

## 1. The Intuitive Approach

Before diving into the algebra, it helps to visualize *why* Dijkstra's algorithm fundamentally works. 

> [!example] The "Strings and Nodes" Analogy
> Imagine the graph is a physical model. 
> - Every vertex is a small metal ring.
> - Every edge is a piece of string tying two rings together. 
> - The length of the string matches the weight of the edge $w(u,v)$.
> 
> **How the algorithm works intuitively:**
> Grab the source ring $s$ and slowly pull it straight up. 
> 1. As you pull, strings become taut. 
> 2. The first ring to be lifted off the table is the one closest to $s$. Once it's in the air, its shortest path string is perfectly straight (finalized).
> 3. As you keep pulling, rings lift off the table one by one, strictly in order of their shortest distance from $s$. 
> 
> **Why we can't find a shorter path later:**
> When a ring $u$ is lifted, could there be a secret, shorter path to it through a ring $y$ that is *still on the table*? 
> **No.** If ring $y$ is still on the table, it means $y$ is further away from $s$ than $u$ is. Any path going through $y$ to get to $u$ would require going *down* to the table and back *up* to $u$. Since strings can't have negative lengths, that path must be longer!

> [!danger] Why Negative Weights Break This
> If a string could have a "negative" length (which physically means going back in time or folding space), a ring still on the table could suddenly propel you higher up. Dijkstra assumes all edge weights are $\ge 0$ (strings can't be negative). If negative weights exist, Dijkstra fails because it finalizes distances too early.

---

## 2. The Mathematical Approach

To mathematically formalize the intuition above, we prove that whenever a vertex $u$ is extracted from the queue (lifted off the table), its calculated distance $d[u]$ is absolutely perfect ($\delta(s, u)$).

> [!tip] The Logical Proof (Simplified)
> Let's prove this without heavy math. Suppose Dijkstra makes a mistake and extracts node $u$, but there is actually a "secret" shorter path to $u$.
> 1. **The Crossing:** This secret shorter path must start at $s$ (which is finalized) and eventually cross into the unvisited nodes. Let $y$ be the very first unvisited node on this secret path.
> 2. **The Trap (No negative weights):** Because there are no negative weights, the rest of the path from $y$ to $u$ can only *add* more distance. This means the true distance to get to $y$ must be less than or equal to the total distance to get to $u$.
> 3. **The Contradiction:** Dijkstra always greedily picks the unvisited node with the absolute smallest current distance. If $y$ is on a shorter path to $u$, $y$ must be closer (or equal) to the source than $u$. Thus, the algorithm would have extracted $y$ before $u$!
> 
> Since Dijkstra chose $u$, our assumption that a secret shorter path exists must be wrong. $u$'s distance is perfectly calculated.

> [!abstract] Theorem 1 (Formal Algebraic Proof)
> When Dijkstra's algorithm terminates, $d[v] = \delta(s, v)$ for every $v \in V$.

We prove this by proving a **Loop Invariant** (a rule that remains true every time the `while` loop runs).

> [!tip] Lemma 1 (Loop Invariant)
> At *every point* during the algorithm, for every vertex $u \in S$ (the set of finalized vertices), 
> $$d[u] = \delta(s, u)$$

**Proof by Strong Induction on $|S|$ (the number of finalized vertices):**

**Base Case ($|S| = 0$):**
$S$ is empty, so the invariant holds vacuously. (When $s$ is extracted, $d[s] = 0 = \delta(s, s)$).

**Inductive Step:**
Assume the invariant holds when $|S| = k$. Let $u$ be the very next vertex extracted from $Q$. $S$ will now grow to $k + 1$. 
*Goal: We must prove that exactly at the moment $u$ is extracted, $d[u] = \delta(s, u)$.*

1. **We know $d[u] \ge \delta(s, u)$:** The algorithm only records real path weights (or $\infty$). It never underestimates. So we just need to prove that $d[u]$ isn't strictly *greater* than the true shortest path. We will prove this by contradiction.
2. **Setup for Contradiction:** Suppose, for contradiction, there is a true shortest path $p$ from $s$ to $u$ that is strictly shorter than our current estimate: $w(p) < d[u]$.
3. **The Cut (The Boundary):** Path $p$ starts at $s$ (which is in $S$) and ends at $u$ (which is currently outside $S$, in $Q$). Therefore, the path *must* cross the boundary between $S$ and $Q$ at some point.
   - Let $(x, y)$ be the *first edge* on path $p$ that crosses this boundary. 
   - So, $x \in S$ (finalized) and $y \notin S$ (still in $Q$).
   
   *Visualizing path $p$:* $\quad s \xrightarrow{p_1} x \xrightarrow{(x,y)} y \xrightarrow{p_2} u$

4. **Decomposing the Path:**
   $$w(p) = w(p_1) + w(x, y) + w(p_2)$$
   
5. **Looking at Node $x$:** Since $x \in S$, by our inductive hypothesis, its distance was perfectly calculated: $d[x] = \delta(s, x) \le w(p_1)$.
6. **Looking at Node $y$:** When $x$ was finalized, we ran the relaxation step on all its neighbors, including $y$. Therefore, $y$'s current estimate is at most the path through $x$:
   $$d[y] \le d[x] + w(x, y) \le w(p_1) + w(x, y)$$
7. **Looking at the rest of the path ($p_2$):** Because there are **no negative weights** in the graph, the remaining path from $y$ to $u$ must be $\ge 0$. So, $w(p_2) \ge 0$.
   Therefore:
   $$d[y] \le w(p_1) + w(x, y) \le w(p_1) + w(x, y) + w(p_2) = w(p)$$
   Since we assumed $w(p) < d[u]$, this implies:
   $$d[y] < d[u]$$

8. **The Contradiction:** We just showed $d[y] < d[u]$. But wait! The algorithm uses `Extract-Min(Q)` and it chose $u$ instead of $y$. If $u$ was chosen, it **must** mean $d[u] \le d[y]$ for all vertices still in $Q$. 
   We have $d[u] \le d[y] < d[u]$, which is impossible! $\blacksquare$

> [!success] Conclusion of Proof
> The contradiction proves that no such shorter path $p$ exists. Therefore, when $u$ is extracted, $d[u] = \delta(s, u)$. Since every vertex is eventually extracted, all distances are correct upon termination.

## 3. Complexity

The time complexity heavily depends on the data structure used for the Priority Queue $Q$.

> [!summary] Time Complexity Breakdown
> The algorithm does:
> - $|V|$ `Extract-Min` operations.
> - At most $|E|$ `Decrease-Key` (Relaxation) operations.
> 
> | Priority Queue Data Structure | `Extract-Min` Cost | `Decrease-Key` Cost | Total Time Complexity |
> | :--- | :--- | :--- | :--- |
> | **Binary Min-Heap** | $O(\log |V|)$ | $O(\log |V|)$ | $O((|V| + |E|) \log |V|)$ |
> | **Fibonacci Heap** | $O(\log |V|)$ | $O(1)$ (amortized) | $O(|V| \log |V| + |E|)$ |

# Bellman-Ford Algorithm: Correctness & Proof

> [!info] Problem Setup
> Let $G = (V, E, w)$ be a weighted directed graph where $n = |V|$.
> - **Weights:** $w : E \to \mathbb{R}$ (Assigns **arbitrary** weights to edges. **Negative weights are permitted**).
> - **Source:** Fix a source vertex $s \in V$.
> - **Shortest-path distance:** Denoted as $\delta(s, v)$. Because negative weights exist, distances can "spiral" down to negative infinity if a negative-weight cycle exists.
> 
> $$ \delta(s, v) = \begin{cases} 
> \min\{w(p)\} & \text{if a path exists AND no negative cycle is reachable} \\ 
> -\infty & \text{if a negative cycle is reachable on a path to } v \\
> \infty & \text{if no path from } s \text{ to } v \text{ exists}
> \end{cases} $$

## The Algorithm

Unlike Dijkstra, Bellman-Ford doesn't greedily "finalize" nodes. Instead, it blindly relaxes **every single edge** in the graph, over and over again, exactly $n-1$ times.

> [!code] Algorithm: Bellman-Ford($G, s$)
> ```python
> 1. d[s] = 0; 
> 2. d[v] = ∞ for all v ≠ s
> 3. 
> 4. # 1. Relaxation Passes
> 5. for i = 1 to n - 1:               # n is the total number of vertices |V|
> 6.     for each edge (u, v) in E:
> 7.         if d[u] + w(u, v) < d[v]: 
> 8.             d[v] = d[u] + w(u, v) # Relax edge (u, v)
> 9. 
> 10. # 2. Negative-Cycle Detection
> 11. for each edge (u, v) in E:
> 12.    if d[u] + w(u, v) < d[v]:
> 13.        report "Negative cycle reachable from s"
> ```

---

## 1. The Intuitive Approach

> [!example] The "Wave of Truth" Analogy
> Think of Bellman-Ford as broadcasting a "wave of truth" across the graph, pass by pass.
> 
> **Why exactly $n-1$ passes?**
> If there are no negative cycles, the longest possible shortest path between any two nodes in a graph with $n$ vertices cannot have more than $n-1$ edges. (If it had $n$ edges, it would visit $n+1$ nodes, meaning it must visit a node twice, creating a cycle. Since it's a *shortest* path and there are no negative cycles, removing this cycle would only make the path shorter or equal).
> 
> - **Pass 1:** Guarantees that any shortest path consisting of exactly **1 edge** is found.
> - **Pass 2:** Builds on Pass 1. Guarantees that any shortest path consisting of **2 edges** is found.
> - **Pass $i$:** The wave has propagated $i$ steps. Any optimal path using $\le i$ edges is guaranteed to be fully discovered.
> - **Pass $n-1$:** The wave has reached the maximum possible length for a simple path. All shortest paths are now perfectly known.

> [!faq] How does it handle Negative Weights?
> Dijkstra fails because it assumes once a node is the "closest," it can never be reached cheaper later. Bellman-Ford never assumes this. By relaxing *every* edge in *every* pass, if a negative weight edge suddenly makes an old path cheaper in Pass 3, the algorithm retroactively corrects the distance and propagates that correction in Pass 4.

---

## 2. The Mathematical Approach

### Proof 1: Correctness (Assuming No Negative Cycles)

> [!tip] The Logical Proof (The Domino Effect)
> Let's prove this without formal induction.
> 1. **The Limit:** In a graph with $V$ vertices, a valid shortest path (with no negative cycles) can never have more than $V-1$ edges. If it had more, it would have to visit a node twice (forming a cycle).
> 2. **The Tracing:** Imagine the absolute shortest path to some destination is the sequence: $s \to a \to b \to c$.
> 3. **Pass 1:** The algorithm blindly relaxes *all* edges. It is guaranteed to evaluate the edge $s \to a$. Now, the distance to $a$ is perfect.
> 4. **Pass 2:** It blindly relaxes all edges again. Since $a$ is already perfect, relaxing the edge $a \to b$ makes $b$'s distance perfect.
> 5. **Pass 3:** Relaxing $b \to c$ makes $c$'s distance perfect.
> 
> **Conclusion:** Like falling dominos, each pass secures at least one more edge along the true shortest path. Since the longest possible path has at most $V-1$ edges, $V-1$ passes mathematically guarantees every domino has fallen, and every node's distance is perfectly calculated.

> [!abstract] Theorem 1 (Formal Algebraic Proof)
> Assume no negative cycle is reachable from $s$. After $n-1$ passes of the outer loop, $d[v] = \delta(s, v)$ for every vertex $v$ reachable from $s$.

**Proof by Strong Induction on $i$ (the number of iterations/edges):**

**Claim:** After $i$ iterations, for every vertex $v$ reachable from $s$ by a shortest path using at most $i$ edges, $d[v] = \delta(s, v)$.

**Base Case ($i = 0$):**
The only vertex reachable from $s$ using $0$ edges is $s$ itself. We initialized $d[s] = 0 = \delta(s, s)$. (Check $\checkmark$)

**Inductive Step:**
Assume the claim holds for $i$ iterations. We want to prove it holds for $i+1$.
1. Let $v$ be a vertex whose true shortest path $P$ from $s$ uses exactly $i+1$ edges:
   $$P = \langle s, \dots, u, v \rangle$$
2. Because shortest paths have **optimal substructure**, the sub-path from $s$ to $u$ must *also* be a true shortest path to $u$, and it uses exactly $i$ edges.
3. By our inductive hypothesis, after $i$ iterations, node $u$'s distance is perfect: 
   $$d[u] = \delta(s, u)$$
4. In the $(i+1)$-th iteration, the algorithm blindly relaxes *every* edge, which means it will explicitly relax edge $(u, v)$. 
5. When $(u, v)$ is relaxed:
   $$d[v] \le d[u] + w(u, v)$$
   $$d[v] \le \delta(s, u) + w(u, v) = \delta(s, v)$$
6. Since algorithms only ever record explicit paths, $d[v]$ can never underestimate the true distance ($d[v] \ge \delta(s, v)$). Therefore, $d[v] = \delta(s, v)$. The invariant is maintained!

**Conclusion:** Since the longest simple path in a graph of $n$ vertices has $n-1$ edges, applying the claim with $i = n-1$ proves that all shortest paths are found. $\blacksquare$

### Proof 2: Negative-Cycle Detection

> [!abstract] Theorem 2
> After $n-1$ passes, there exists an edge $(u, v) \in E$ where $d[u] + w(u, v) < d[v]$ **if and only if** a negative cycle is reachable from $s$.

**Proof:**
- **($\Leftarrow$ If NO negative cycle exists):** By Theorem 1, after $n-1$ passes, all $d[v] = \delta(s,v)$. By the triangle inequality for shortest paths, $\delta(s, v) \le \delta(s, u) + w(u, v)$. Therefore $d[v] \le d[u] + w(u, v)$ for all edges. No edge will trigger the detection condition.
- **($\Rightarrow$ If an edge DOES trigger detection):** Suppose $d[u] + w(u, v) < d[v]$ after $n-1$ passes. This means the distances have *not* stabilized. If we kept relaxing, paths would require $\ge n$ edges. By the Pigeonhole Principle, any walk on $n$ vertices with $\ge n$ edges must repeat a vertex, forming a cycle. 
  - If the cycle had a positive or zero weight, removing it would yield a shorter (or equal) path with $< n$ edges, which we would have found already.
  - Therefore, the cycle *must* have a strictly negative weight. Because it keeps decreasing our $d[\cdot]$ values, it is reachable from $s$. $\blacksquare$

## 3. Complexity

Because Bellman-Ford iterates over all edges multiple times, its time complexity is straightforward to calculate, though higher than Dijkstra's.

> [!summary] Time Complexity Breakdown
> - **Outer Loop:** Executes exactly $|V| - 1$ times.
> - **Inner Loop:** Iterates over all $|E|$ edges in every pass.
> - **Detection Step:** One final pass over all $|E|$ edges.
> 
> **Total Time Complexity:** 
> $$T(|V|, |E|) = O(|V| \cdot |E|)$$
> 
> *Note: While $O(|V| \cdot |E|)$ is mathematically "worse" than Dijkstra's $O((|V|+|E|) \log |V|)$ on non-negative graphs, Bellman-Ford provides the critical ability to process negative weights and detect negative cycles, which Dijkstra physically cannot do.*
