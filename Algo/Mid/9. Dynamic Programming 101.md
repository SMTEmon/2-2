# 🧠 Part I: Fundamentals & Fibonacci

> [!abstract] What is Dynamic Programming?
> Dynamic Programming (DP) is essentially an optimization over plain recursion. 
> **Core Idea:** Don't solve the same sub-problem twice. Break a big problem into smaller pieces, solve each piece once, remember the answer, and reuse it.

## 🧱 The Two Necessary Ingredients for DP
For a problem to be solvable (and optimizable) using DP, it must possess two properties:

1. **Overlapping Subproblems:** The same smaller problems are solved repeatedly. Without this, DP gives no benefit over standard recursion (e.g., Merge Sort doesn't have overlapping subproblems, so DP doesn't help).
2. **Optimal Substructure:** The optimal solution to the overall problem can be constructed from the optimal solutions of its subproblems.

### 🚩 Signs a problem might need DP
* You are asked to **count the number of ways** to do something.
* You need to find the **minimum/maximum** value.
* You need to **make decisions repeatedly** (e.g., take a coin or don't take a coin).
* The problem can be broken down into smaller versions of itself.

---

## 🍳 The DP Recipe
To solve any DP problem, follow these exact steps:
1. **Define the State:** What do the parameters of your function (or indices of your array) represent? (e.g., `dp[i]` = the $i$-th Fibonacci number).
2. **Define the Recurrence Relation:** How do you combine previous results to get the current result?
3. **Identify Base Cases:** What are the simplest, non-reducible subproblems?
4. **Compute/Store Answers:** Use an array, matrix, or hash map to store results.
5. **Return the Desired State:** Usually the last element in your DP table.

---

## 📈 The Classic Example: Fibonacci Sequence

**Problem:** Find the $n$-th Fibonacci number. 
Sequence: `1, 1, 2, 3, 5, 8, 13, 21...`
Recurrence: $F(n) = F(n-1) + F(n-2)$

### 1. Naive Recursion

> [!danger] The Problem with Plain Recursion
> Calling `fib(5)` calculates `fib(3)` twice. Calling `fib(40)` makes over **300 million** calls.

**Pseudocode:**
```text
FUNCTION fib(n):
    IF n <= 1:
        RETURN n
    RETURN fib(n-1) + fib(n-2)
```

**C++ Code:**
```cpp
int fib(int n) {
    if(n <= 1) return n;
    return fib(n-1) + fib(n-2);
}
```

#### ⏱️ Complexity Calculation: Naive Recursion
* **Time Complexity:** $\mathcal{O}(2^n)$ - Exponential.
  * *Step-by-step:* Think of the recursive calls as a binary tree. Every call branches into two more calls (`n-1` and `n-2`). The tree has a depth of $n$. The number of nodes in a complete binary tree of depth $n$ is roughly $2^n - 1$. Therefore, the total number of operations grows exponentially.
* **Space Complexity:** $\mathcal{O}(n)$ - Linear.
  * *Step-by-step:* Space complexity in recursion depends on the maximum depth of the **call stack**. The longest path down the execution tree is `fib(n)` $\rightarrow$ `fib(n-1)` $\rightarrow$ ... $\rightarrow$ `fib(0)`. This requires $n$ stack frames in memory at the same time.

---

### 2. Top-Down DP (Memoization)
Start from the big problem, recurse downward, but **cache (memoize)** the results in an array.

**Pseudocode:**
```text
GLOBAL ARRAY dp INITIALIZED TO -1

FUNCTION fib(n):
    IF n <= 1:
        RETURN n
        
    // If already computed, return the cached value
    IF dp[n] != -1:
        RETURN dp[n]
        
    // Otherwise compute, cache, and return
    dp[n] = fib(n-1) + fib(n-2)
    RETURN dp[n]
```

**C++ Code:**
```cpp
// Assume dp is initialized to -1, e.g., vector<int> dp(n+1, -1);
int fib(int n) {
    if(n <= 1) return n;
    
    if(dp[n] != -1) 
        return dp[n];
        
    return dp[n] = fib(n-1) + fib(n-2);
}
```

#### ⏱️ Complexity Calculation: Memoization
* **Time Complexity:** $\mathcal{O}(n)$ - Linear.
  * *Step-by-step:* Total Time = (Number of unique subproblems) $\times$ (Time to solve each subproblem). We have $n$ unique states (`fib(1)` to `fib(n)`). Combining them takes $O(1)$ constant time (just addition). $n \times O(1) = \mathcal{O}(n)$.
* **Space Complexity:** $\mathcal{O}(n)$ - Linear.
  * *Step-by-step:* We need an array `dp` of size $n+1$ which takes $\mathcal{O}(n)$ space. Furthermore, the recursion call stack still goes $n$ levels deep, taking another $\mathcal{O}(n)$ space. Overall: $\mathcal{O}(n) + \mathcal{O}(n) = \mathcal{O}(n)$.

---

### 3. Bottom-Up DP (Tabulation)
Start from the base cases and fill up a table iteratively. **No recursion overhead.**

**Pseudocode:**
```text
FUNCTION fib(n):
    IF n <= 1:
        RETURN n
        
    CREATE ARRAY dp OF SIZE n+1
    dp[0] = 0
    dp[1] = 1
    
    FOR i FROM 2 TO n:
        dp[i] = dp[i-1] + dp[i-2]
        
    RETURN dp[n]
```

**C++ Code:**
```cpp
int fib(int n) {
    if (n <= 1) return n;
    vector<int> dp(n + 1);
    
    dp[0] = 0;
    dp[1] = 1;
    
    for(int i = 2; i <= n; i++) {
        dp[i] = dp[i-1] + dp[i-2];
    }
    return dp[n];
}
```

#### ⏱️ Complexity Calculation: Tabulation
* **Time Complexity:** $\mathcal{O}(n)$ - Linear.
  * *Step-by-step:* We have a single `for` loop that runs from $2$ to $n$. Inside the loop, we perform a single addition $\mathcal{O}(1)$. Therefore, $n \times \mathcal{O}(1) = \mathcal{O}(n)$.
* **Space Complexity:** $\mathcal{O}(n)$ - Linear.
  * *Step-by-step:* We allocate an array of size $n+1$. Because we are iterating, there is **no recursion call stack** taking up extra memory. Total space is just the array $\mathcal{O}(n)$.

---

### 4. Space-Optimized Bottom-Up DP
Notice in Tabulation that `dp[i]` only depends on the **last two values** (`dp[i-1]` and `dp[i-2]`). We don't need to keep the whole array!

**Pseudocode:**
```text
FUNCTION fib(n):
    IF n <= 1:
        RETURN n
        
    prev2 = 0 // corresponds to dp[i-2]
    prev1 = 1 // corresponds to dp[i-1]
    
    FOR i FROM 2 TO n:
        current = prev1 + prev2
        prev2 = prev1
        prev1 = current
        
    RETURN prev1
```

**C++ Code:**
```cpp
int fib(int n) {
    if (n <= 1) return n;
    int a = 0; // dp[i-2]
    int b = 1; // dp[i-1]
    int c;     // dp[i]
    
    for(int i = 2; i <= n; i++) {
        c = a + b;
        a = b;
        b = c;
    }
    return b;
}
```

#### ⏱️ Complexity Calculation: Optimized
* **Time Complexity:** $\mathcal{O}(n)$ - Linear.
  * *Step-by-step:* The `for` loop still runs $n-1$ times doing constant time arithmetic.
* **Space Complexity:** $\mathcal{O}(1)$ - Constant.
  * *Step-by-step:* We are only declaring three integer variables (`a`, `b`, `c`). No matter how large $n$ gets, memory usage stays exactly the same.

---

## 🆚 Summary: Memoization vs Tabulation

| Feature | Memoization (Top-Down) | Tabulation (Bottom-Up) |
| :--- | :--- | :--- |
| **Intuition** | Natural extension of recursion. Easy to think about. | Harder to visualize initially. Needs explicit loop order. |
| **Efficiency** | Slower in practice due to function call stack overhead. | Faster. Loop iterations are highly optimized by compilers. |
| **Subproblems** | Only computes subproblems that are strictly necessary. | Computes **all** subproblems up to $n$ sequentially. |
| **Space** | $\mathcal{O}(N)$ Array + $\mathcal{O}(N)$ Recursion Stack | $\mathcal{O}(N)$ Array (can often be optimized to $\mathcal{O}(1)$) |

# 🪙 Part II: The Coin Change Family

> [!info] Problem Statement (Home Task)
> **Given:** An array of coin denominations: `coins = {1, 3, 4}` and a target amount `6`. 
> **Constraint:** A coin denomination may be used any number of times.

There are three main variations of this problem discussed in the lectures:
1. Minimum number of coins needed.
2. Number of ways to make the target (Permutations: order *matters*).
3. Number of ways to make the target (Combinations: order *doesn't matter*).

---

## Variation 1: Minimum Coins to Make Target

### 1. The DP Recipe Application
*   **State:** `dp[x]` = minimum number of coins needed to make value `x`. We want `dp[6]`.
*   **Recurrence:** To make value `x`, try using *each* coin. Take the minimum of those choices and add 1 (for the coin you just placed).
    $$dp[x] = \min_{c \in coins}(dp[x-c]) + 1$$
*   **Base Case:** To make target `0`, you need `0` coins.
    $$dp[0] = 0$$
    *(Note: Initialize other values to infinity / `INT_MAX` since we are searching for a minimum)*

### 2. Solutions: Recursive $\rightarrow$ Memoized $\rightarrow$ Tabulated

> [!example]- Recursive & Memoized Implementations (Click to Expand)
> **Pure Recursive (Time: $O(C^N)$, Space: $O(N)$)**
> ```cpp
> #include <bits/stdc++.h>
> using namespace std;
> const int INF = 1e9;
> 
> int solve(int x) {
>     if (x == 0) return 0;
>     if (x < 0) return INF;
>     
>     return 1 + min({
>         solve(x - 1),
>         solve(x - 3),
>         solve(x - 4)
>     });
> }
> ```
> 
> **Memoized / Top-Down DP (Time: $O(N \cdot C)$, Space: $O(N)$)**
> ```cpp
> // Initialize vector<int> dp(target + 1, -1);
> int solve(int x) {
>     if (x == 0) return 0;
>     if (x < 0) return INF;
>     
>     if (dp[x] != -1) return dp[x];
>     
>     return dp[x] = 1 + min({
>         solve(x - 1),
>         solve(x - 3),
>         solve(x - 4)
>     });
> }
> ```

**Tabulation / Bottom-Up Code (Dynamic input coins):**
```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> coins = {1, 3, 4};
    int target = 6;
    
    // Initialize array of size target+1 with a very large number
    vector<int> dp(target + 1, 1e9); 
    
    // Base Case
    dp[0] = 0; 
    
    for (int i = 1; i <= target; i++) {
        for (int coin : coins) {
            // Only update if the coin is not larger than current target sum 'i'
            if (i >= coin) {
                dp[i] = min(dp[i], dp[i - coin] + 1);
            }
        }
    }
    
    cout << "Minimum coins needed: " << dp[target] << '\n';
    return 0;
}
```

#### ⏱️ Complexity Calculation
Let $N$ be the target amount and $C$ be the number of different coin denominations.
*   **Time Complexity:** $\mathcal{O}(N \times C)$
    *   *Step-by-step:* The outer `for` loop runs $N$ times (from `1` to `target`). Inside, the inner `for` loop iterates over every coin, running $C$ times. The operation inside the inner loop is a constant-time `min()` check. Total operations = $N \times C \times \mathcal{O}(1) = \mathcal{O}(N \times C)$.
*   **Space Complexity:** $\mathcal{O}(N)$
    *   *Step-by-step:* We allocate a single 1D array `dp` of size $N + 1$. No recursion stack is used.

## Variation 2: Number of Ways (Permutations)

> [!abstract] Permutation Definition
> Order **matters**. For target `4` with coins `{1, 3}`, the sequences `{1, 3}` and `{3, 1}` are considered **two different ways**.

### 1. The DP Recipe Application
*   **State:** `dp[x]` = number of distinct permutations to make amount `x`.
*   **Recurrence:** Sum up the number of ways to form `x - coin` for every available coin.
    $$dp[x] = \sum_{c \in coins} dp[x-c]$$
*   **Base Case:** There is exactly `1` way to make the amount `0` (by choosing nothing). `dp[0] = 1`.

### 2. Memoization Code (Top-Down)

```cpp
// Initialize vector<long long> dp(target + 1, -1);
long long solve(int x, const vector<int>& coins, vector<long long>& dp) {
    if (x == 0) return 1; // Base case: successfully formed the target
    if (x < 0) return 0;  // Base case: overshot the target
    
    if (dp[x] != -1) return dp[x];
    
    long long ways = 0;
    for (int c : coins) {
        ways += solve(x - c, coins, dp);
    }
    
    return dp[x] = ways;
}
```

### 3. Tabulation Code (Target as Outer Loop)
```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> coins = {1, 3, 4};
    int target = 6;
    
    vector<long long> dp(target + 1, 0);
    dp[0] = 1; // Base case
    
    // 1. OUTER LOOP: Iterate through all target values
    for (int i = 1; i <= target; i++) {
        // 2. INNER LOOP: Iterate through all coins
        for (int c : coins) {
            if (i >= c) {
                dp[i] += dp[i - c];
            }
        }
    }
    
    cout << dp[target] << '\n';
    return 0;
}
```

## Variation 3: Number of Ways (Combinations)

> [!abstract] Combination Definition
> Order **does not matter**. For target `4` with coins `{1, 3}`, the sequences `{1, 3}` and `{3, 1}` are considered the **exact same way** (just a set of one `1` and one `3`).

### 1. The DP Recipe Application (Memoization Requires 2D State)
To enforce that order doesn't matter in top-down DP, we must prevent the algorithm from looking back at previous coins. This requires adding a **second state parameter**: the current coin index.
*   **State:** `dp[index][x]` = number of combinations to make amount `x` using only coins from `index` to the end.
*   **Recurrence:** Try taking the current coin, and try skipping it.
    $$dp[index][x] = take\_current\_coin + skip\_current\_coin$$
*   **Base Cases:** If `x == 0`, `1` way. If `x < 0` or `index` is out of bounds, `0` ways.

### 2. Memoization Code (Top-Down 2D)

```cpp
// Initialize 2D vector: vector<vector<long long>> dp(coins.size(), vector<long long>(target + 1, -1));
long long solve(int index, int x, const vector<int>& coins, vector<vector<long long>>& dp) {
    if (x == 0) return 1; // Target reached
    if (index >= coins.size() || x < 0) return 0; // Invalid state
    
    if (dp[index][x] != -1) return dp[index][x];
    
    // Choice 1: Take the current coin (stay on the same index since we can reuse it)
    long long take = solve(index, x - coins[index], coins, dp);
    
    // Choice 2: Skip the current coin and move to the next index
    long long skip = solve(index + 1, x, coins, dp);
    
    return dp[index][x] = take + skip;
}
```

### 3. Tabulation Code (Coins as Outer Loop)
```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> coins = {1, 3, 4};
    int target = 6;
    
    vector<long long> dp(target + 1, 0);
    dp[0] = 1; // Base case
    
    // 1. OUTER LOOP: Iterate through coins FIRST
    for (int coin : coins) {
        // 2. INNER LOOP: Iterate through all target values
        for (int sum = coin; sum <= target; sum++) {
            dp[sum] += dp[sum - coin];
        }
    }
    
    cout << dp[target] << '\n';
    return 0;
}
```

## 🕵️ The Big Question: Why Does Loop Order Matter?

Lecture 13, Slide 22 warns: *"Caution: The order of the loop has to be reversed. Why?"*
Here is the definitive algorithmic explanation.

### Scenario A: Target Sum is the Outer Loop (Permutations)
```cpp
for target in 1...N:
    for coin in coins:
```
*   **How it builds:** At target `4`, we evaluate adding a `3` to target `1` (which gives `{1, 3}`), AND we evaluate adding a `1` to target `3` (which gives `{3, 1}`). 
*   **Result:** Because every target sum considers *every coin* over and over again, we are traversing all possible unique paths to reach a sum. It counts permutations.

### Scenario B: Coin is the Outer Loop (Combinations)
```cpp
for coin in coins:
    for target in coin...N:
```
*   **How it builds:** We process entirely **one coin at a time**. 
    1. First, we calculate all ways to make sums using **ONLY** the `1` coin. 
    2. *Then*, we move to the `3` coin. We ask: "How many ways can I reach this sum by adding a `3` to the sums I previously built?"
*   **Result:** Because we completely finish processing the `1` coin before we ever look at the `3` coin, it is **impossible** to place a `1` *after* a `3`. We have forced an artificial ordering rule ($c_1 \le c_2 \le c_3...$). Since order is forced, `{3, 1}` is completely impossible to generate. It only counts `{1, 3}`. Thus, we get unique combinations!

> [!summary] Rule of Thumb
> *   If order matters (Permutations): `Target` loop outside, `Coins` loop inside.
> *   If order doesn't matter (Combinations): `Coins` loop outside, `Target` loop inside.
> 
> *Both variations have the exact same time $\mathcal{O}(N \times C)$ and space $\mathcal{O}(N)$ complexities!*

# 🧑‍🤝‍🧑 Part III: Combinatorics & Pathing

## 👥 Friend's Pairing Problem

> [!info] Problem Statement
> Given $n$ friends, each one can either remain single or be paired up with some other friend. Each friend can be paired only once. Find out the total number of ways in which friends can remain single or be paired up.
> *(Note: Order doesn't matter for pairs. `{1, 2}` is the same as `{2, 1}`)*

### 1. The DP Recipe Application
*   **State:** `dp[i]` = total number of ways to arrange `i` friends.
*   **Recurrence:** Let's look at the $i$-th person. They have two choices:
    1.  **Remain Single:** There is $1$ way to do this. The remaining $i-1$ people must be arranged. This yields $1 \times dp[i-1]$ ways.
    2.  **Pair Up:** The $i$-th person can pair up with ANY of the remaining $i-1$ people. Once paired, there are $i-2$ people left to arrange. This yields $(i-1) \times dp[i-2]$ ways.
    **Recurrence Relation:**
    $$dp[i] = dp[i-1] + (i-1) \times dp[i-2]$$
*   **Base Cases:** 
    *   `dp[0] = 0` (0 ways for 0 friends - conceptually, or `dp[0]=1` empty set. The code handles this via `i <= 2` logic).
    *   `dp[1] = 1` (1 friend can only be single: `{1}`).
    *   `dp[2] = 2` (2 friends can be single `{1}, {2}` or paired `{1, 2}`).

### 2. Memoization Code (Top-Down)

**Pseudocode:**
```text
GLOBAL ARRAY dp INITIALIZED TO -1

FUNCTION countFriendsPairings(n):
    IF n <= 2:
        RETURN n
        
    IF dp[n] != -1:
        RETURN dp[n]
        
    dp[n] = countFriendsPairings(n-1) + (n-1) * countFriendsPairings(n-2)
    RETURN dp[n]
```

**C++ Code:**
```cpp
// Initialize vector<int> dp(n + 1, -1);
int countFriendsPairings(int n, vector<int>& dp) {
    if (n <= 2) return n;
    
    if (dp[n] != -1) return dp[n];
    
    return dp[n] = countFriendsPairings(n - 1, dp) + (n - 1) * countFriendsPairings(n - 2, dp);
}
```

### 3. Tabulation Code (Bottom-Up)

**Pseudocode:**
```text
FUNCTION countFriendsPairings(n):
    CREATE array dp OF SIZE n + 1
    
    FOR i FROM 0 TO n:
        IF i <= 2:
            dp[i] = i
        ELSE:
            dp[i] = dp[i-1] + (i-1) * dp[i-2]
            
    RETURN dp[n]
```

**C++ Code:**
```cpp
int countFriendsPairings(int n) {
    // Array to store DP results
    vector<int> dp(n + 1);
    
    // Filling dp[] in bottom-up manner
    for (int i = 0; i <= n; i++) {
        if (i <= 2) {
            dp[i] = i; 
        } else {
            dp[i] = dp[i - 1] + (i - 1) * dp[i - 2];
        }
    }
    
    return dp[n];
}
```

#### ⏱️ Complexity Calculation
*   **Time Complexity:** $\mathcal{O}(n)$ - Linear.
    *   *Step-by-step:* We loop from `0` to `n`. Inside the loop, we perform basic arithmetic (addition and multiplication) and array lookups. These are $\mathcal{O}(1)$ operations. Total time = $n \times \mathcal{O}(1) = \mathcal{O}(n)$.
*   **Space Complexity:** $\mathcal{O}(n)$ - Linear.
    *   *Step-by-step:* We allocate an array of size $n+1$ to store the states. No recursion stack overhead is present. *(Note: Just like Fibonacci, this can be space-optimized to $\mathcal{O}(1)$ by keeping track of only `prev1` and `prev2`!)*

## 🧗 Climbing Stairs Problem (Missing Solution Filled In)

> [!example] Problem Statement (Lecture 12, Slide 21)
> You can climb **1, 2, or 3** steps at a time. How many ways are there to reach step $n$?

This is an extension of the staircase analogy from earlier, expanding the allowed steps from `[1, 2]` to `[1, 2, 3]`.

### 1. The DP Recipe Application
*   **State:** `dp[i]` = total number of distinct ways to reach the $i$-th step.
*   **Recurrence:** To reach step $i$, what was your very last move? 
    *   You could have been at step $i-1$ and took a 1-step.
    *   You could have been at step $i-2$ and took a 2-step.
    *   You could have been at step $i-3$ and took a 3-step.
    **Recurrence Relation:**
    $$dp[i] = dp[i-1] + dp[i-2] + dp[i-3]$$
*   **Base Cases:**
    *   `dp[0] = 1` (1 way to stay on the ground - do nothing).
    *   `dp[1] = 1` (1 way to reach step 1: `[1]`).
    *   `dp[2] = 2` (2 ways to reach step 2: `[1,1]` or `[2]`).

### 2. Memoization Code (Top-Down)

**Pseudocode:**
```text
GLOBAL ARRAY dp INITIALIZED TO -1

FUNCTION countWaysToClimb(n):
    IF n == 0 OR n == 1: RETURN 1
    IF n == 2: RETURN 2
    
    IF dp[n] != -1:
        RETURN dp[n]
        
    dp[n] = countWaysToClimb(n-1) + countWaysToClimb(n-2) + countWaysToClimb(n-3)
    RETURN dp[n]
```

**C++ Code:**
```cpp
#include <vector>
using namespace std;

// Initialize vector<int> dp(n + 1, -1);
int countWaysToClimb(int n, vector<int>& dp) {
    if (n <= 1) return 1;
    if (n == 2) return 2;
    
    if (dp[n] != -1) return dp[n];
    
    return dp[n] = countWaysToClimb(n - 1, dp) + countWaysToClimb(n - 2, dp) + countWaysToClimb(n - 3, dp);
}
```

### 3. Tabulation Code (Bottom-Up)

**Pseudocode:**
```text
FUNCTION countWaysToClimb(n):
    // Handle edge cases
    IF n == 0 OR n == 1: RETURN 1
    IF n == 2: RETURN 2
    
    CREATE array dp OF SIZE n + 1
    dp[0] = 1
    dp[1] = 1
    dp[2] = 2
    
    FOR i FROM 3 TO n:
        dp[i] = dp[i-1] + dp[i-2] + dp[i-3]
        
    RETURN dp[n]
```

**C++ Code:**
```cpp
#include <vector>
using namespace std;

int countWaysToClimb(int n) {
    if (n <= 1) return 1;
    if (n == 2) return 2;
    
    vector<int> dp(n + 1, 0);
    dp[0] = 1;
    dp[1] = 1;
    dp[2] = 2;
    
    for (int i = 3; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2] + dp[i - 3];
    }
    
    return dp[n];
}
```

#### ⏱️ Complexity Calculation
*   **Time Complexity:** $\mathcal{O}(n)$ - Linear.
    *   *Step-by-step:* The `for` loop iterates from `3` to `n`. In each iteration, we do two additions and three array lookups, which takes constant $\mathcal{O}(1)$ time. Overall time is $n \times \mathcal{O}(1) = \mathcal{O}(n)$.
*   **Space Complexity:** $\mathcal{O}(n)$ - Linear.
    *   *Step-by-step:* We are utilizing a `vector` (array) of size $n+1$. 
    *   *Bonus Optimization:* Because we only ever look back `3` steps (`i-1`, `i-2`, `i-3`), we could easily optimize this to $\mathcal{O}(1)$ space by using three variables (`a, b, c`), exactly like the optimized Fibonacci approach!
